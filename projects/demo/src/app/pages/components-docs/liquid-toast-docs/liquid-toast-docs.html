Liquid toast

Toasts with Sonner's API and the app's own motion. Call toast() from anywhere; a card grows out of a drop at the screen edge — or out of the element it belongs to — and gathers back into it when it goes.

Every button below calls the real thing. The page carries its own toaster, so what you see is what the app does.

One <x-liquid-toaster> anywhere the app is always mounted; then call toast() from anywhere at all, with no injection.

Examples

Types

Each type is only a hue: the plate and the icon derive from it with lightness and chroma pinned. default has no icon; loading spins and stays until it is updated.

Description

A second, quieter line. Long text wraps, and the card is sized to it before it grows — so nothing re-wraps mid-flight.

Action & cancel

The main button and a quieter one beside it. The toast dismisses itself after a button's onClick — unless that calls event.preventDefault().

Update in place

Pass an existing id and that toast changes where it stands: the card resizes to its new content before the content swaps, and the countdown starts over. Press once to start it, again to finish it.

Promise

One toast follows the work: loading, then success or error. Messages can be strings, functions of the result, or {{ '{' }} title, description {{ '}' }}. This one fails about a third of the time, on purpose. 

{{ code.promise }}

No auto dismiss

autoDismiss: false keeps a toast until it is closed, and gives it a close button unless closeButton: false or dismissible: false says otherwise.

Overflow ghost

Past visibleToasts, a ghost pill after the last card counts what is waiting. Click it to show them all — the stack scrolls if it outgrows the screen — and “Show less” to fold them back. A waiting toast does not count down until it shows.

Countdown pill

Off by default. With timer: 'hover', hovering a toast grows a pill out of its side with the time left, its digits popping like numberPopIn. It faces into the screen, and hovering holds the count where it is unless pauseOnHover: false says otherwise.

From a target

A toast can grow out of an element rather than the screen edge, stack beside it, and gather back into it — so a save answers from the thing that was saved. The element gives a small squash as each one leaves it. While the target is missing or hidden, its toasts go to the fallback edge instead.

It appears beside this button rather than at a screen edge, and stays until dismissed — a toast that sees itself out in four seconds is hard to look at while reading about it.
